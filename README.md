# WMS-AI — робоче місце аналітика 1С на Claude Code

Проєкт-оснастка для **аналітика** конфігурації 1С **WMS**: допомагає швидко розібратися, як задача реалізована
в конфігурації зараз, знайти схожі задачі в Jira і підготувати розробнику зрозумілий план реалізації — задачу в Jira.

Код конфігурації тут **не пишеться і не змінюється**: усі інструменти працюють лише на читання
(вивантаження конфігурації, індекс коду, тестова база, Jira/Confluence).

Працює з тільки з вивантаженною та проіндексованною конфигурацією через MCP-1С сервер
Для роботи з данними потребує встановленного та налаштованного MCP-SQL сервер

## Що вміє

| Можливість | Як |
|---|---|
| Проаналізувати помилку або доробку | `/analyze` — аналіз поточної реалізації → схожі задачі в Jira → причина / план у чат. У Jira нічого не пише |
| Поставити задачу, додати коментар, оновити задачу | `/jira-task` — лише на явне прохання: чернетка з аналізу → погодження → створення / коментар / оновлення в Jira |
| Ретроспектива сесії - складає коротку вижимку з поточного контексту | `/session-retro` — лише на явне прохання. Повертає структурований ретро аналіз поточної сессії |
| Відповісти «де/як це зроблено» | пошук по індексу коду і вивантаженню, з посиланнями `Об'єкт → Модуль → Процедура` |
| Отримати данні з бази для перевірки гіпотез | Можна отримати реальні данні з бази SQL (для читання,тільки SELECT) |

## Технічні скіли 
Додатково використовуються скіли які допомогають клоду зробити аналіз конфигурації

| Можливість | Як |
|---|---|
| Розпарсити не керовану форму та витягти структуру форми та код | `/form-bin` — підключається автоматично при аналізі форми якщо код не був повернутий від MCP серверу|
| Розпарсити керовану форму/СКД/макет та витягти структуру та код | `/inspect` — підключається автоматично при аналізі об'єкту якщо об'єкт у читаємому форматі (XML|MXL) |
| Пояснити клоду як шукати реальну таблицю данних у SQL якщо запит написан на SQL з використанням View | `/1c-sql-structure` — підключається автоматично при аналізі SQL запиту |
| Оновити вивантаження конфігурації | `/1c-batch` — лише на явне прохання дозволяє вивантажити метаданні конфигурації |

### Сценарій `/analyze`

1. Уточнюючі питання (лише те, чого не можна знайти самостійно).
2. Аналіз поточної реалізації: код (1c-rag → Grep по вивантаженню й кешу форм), метадані, форми, ролі, меню,
   збережені процедури SQL, дані тестової бази.
3. Пошук схожих задач у Jira і того, як їх було реалізовано.
4. Причина або план реалізації з доказами (код, метадані, результати запитів); гіпотези позначено. Результат — у чаті.

### Сценарій `/jira-task`

Викликається лише коли користувач просить змінити щось у Jira. Режими: **створити задачу**, **додати коментар**,
**оновити задачу** (опис, критерії, зв'язки). Бере аналіз `/analyze` з поточної розмови, показує повний текст
один раз на погодження, після «ок» виконує — і лише те, що попросили.

## Джерела даних

| Що | Де |
|---|---|
| Вивантаження конфігурації (XML + BSL) | `configuration\` (корінь — `Configuration.xml`) — **не в репозиторії** |
| Модулі звичайних форм як `.bsl` (кеш) | `.formbin-cache\` — генерується `/form-bin`, **не в репозиторії** |
| Індекс коду й метаданих | MCP `1c-rag` (Docker, за замовчуванням `http://localhost:9000/mcp`) |
| Дані бази | MCP `mssql-mcp` (Docker, за замовчуванням `http://localhost:9001/mcp`) |
| Постановки, історія задач | MCP `atlassian` (Jira, Confluence) — на рівні користувача, токен особистий |

## Структура репозиторію

```
CLAUDE.md                 правила роботи агента: де шукати код, порядок пошуку, правила MCP
.mcp.json                 підключення 1c-rag і mssql-mcp
.claude/settings.json     увімкнені MCP-сервери проєкту
.claude/skills/           скіли: analyze, jira-task, inspect, form-bin, 1c-sql-structure, 1c-batch, session-retro
.claude/docs/             специфікації XML-формату вивантаження 1С (конфігурація, об'єкти, форми, СКД, ролі, MXL…)
```

## Встановлення

1. Встановити [Claude Code](https://claude.com/claude-code) і клонувати репозиторій.
2. Створити каталог `configuration\` якщо його ще нема.
3. Покласти вивантаження конфігурації в `configuration\` (через конфігуратор або `/1c-batch dump-config`).
   Для `/1c-batch` — скопіювати `.claude/skills/1c-batch/assets/.1c-devbase.ps1.example` у `.1c-devbase.ps1`
   і вказати параметри бази (файл не комітити).
4. Запустити Docker-контейнери `1c-rag` (проіндексувати цю ж конфігурацію) і `mssql-mcp`
5. Вказати у mssql-mcp параметри підключення до серверу SQL (користувач з правами read only)
6. Підключити MCP `atlassian` у `~/.claude.json` з особистим токеном. 
   
**Одна конфігурація — одна копія проєкту:** 1c-rag індексує лише одну конфігурацію, тому для кожної конфігурації
потрібні свій контейнер 1c-rag і своя копія цього проєкту.

## Обмеження

- Індекс 1c-rag не містить підписок на події, регламентних завдань, модулів застосунку/сеансу,
  текстів запитів СКД і текстових макетів — їх агент читає з файлів вивантаження.
