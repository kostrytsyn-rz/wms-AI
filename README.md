# WMS-AI — робоче місце аналітика 1С на Claude Code

Проєкт-оснастка для **аналітика** конфігурації 1С **WMS**: допомагає швидко розібратися, як задача реалізована
в конфігурації зараз, знайти схожі задачі в Jira і підготувати розробнику зрозумілий план реалізації — задачу в Jira.

Код конфігурації тут **не пишеться і не змінюється**: усі інструменти працюють лише на читання
(вивантаження конфігурації, індекс коду, тестова база, Jira/Confluence).

## Що вміє

| Можливість | Як |
|---|---|
| Розібрати помилку або доробку і поставити задачу розробнику | `/brainstorm` — аналіз поточної реалізації → схожі задачі в Jira → план → чернетка задачі → створення в Jira після погодження |
| Відповісти «де/як це зроблено» | пошук по індексу коду і вивантаженню, з посиланнями `Об'єкт → Модуль → Процедура` |
| Прочитати структуру об'єктів з XML | `/inspect`: конфігурація, об'єкт метаданих, керована форма, СКД, MXL-макет, підсистема, роль і права |
| Прочитати **звичайні форми** (`Form.bin`) | `/form-bin`: елементи, сторінки, кнопки → обробники, текст модуля
| Отримати данні з бази для перевірки гіпотез | `/1c-sql-structure` + MCP `mssql-mcp`: об'єкт 1С ↔ таблиця/view, розшифровка `_InfoRg326`, дати +2000, тексти збережених процедур SQL (тільки SELECT) |
| Знайти, що оптимізувати в повільному запиті/звіті | `/1c-query-opt` |
| Оновити вивантаження конфігурації | `/1c-batch` (`dump-config`, повне або `update`) + оновлення кешу форм |
| Ретроспектива сесії | `/session-retro` |

### Сценарій `/brainstorm`

1. Уточнюючі питання (лише те, чого не можна знайти самостійно).
2. Аналіз поточної реалізації: код (1c-rag → Grep по вивантаженню й кешу форм), метадані, форми, ролі, меню,
   збережені процедури SQL, дані тестової бази.
3. Пошук схожих задач у Jira і того, як їх було реалізовано.
4. План реалізації для розробника з доказами (код, метадані, результати запитів); гіпотези позначено.
5. Одна точка погодження — чернетка задачі. Після «ок» задача створюється в Jira.

## Джерела даних

| Що | Де |
|---|---|
| Вивантаження конфігурації (XML + BSL) | `configuration\` (корінь — `Configuration.xml`) — **не в репозиторії** |
| Модулі звичайних форм як `.bsl` (кеш) | `.formbin-cache\` — генерується `/form-bin`, **не в репозиторії** |
| Індекс коду й метаданих | MCP `1c-rag` (Docker, за замовчуванням `http://localhost:9000/mcp`) |
| Дані бази | MCP `mssql-mcp` (Docker, за замовчуванням `http://localhost:9001/mcp`) |
| Постановки, історія задач | MCP `atlassian` (Jira, Confluence) — на рівні користувача, токен особистий |

## Структура репозиторію

```
CLAUDE.md                 правила роботи агента: де шукати код, порядок пошуку, правила MCP
.mcp.json                 підключення 1c-rag і mssql-mcp
.claude/settings.json     увімкнені MCP-сервери проєкту
.claude/skills/           скіли: brainstorm, inspect, form-bin, 1c-sql-structure, 1c-query-opt, 1c-batch, session-retro
.claude/docs/             специфікації XML-формату вивантаження 1С (конфігурація, об'єкти, форми, СКД, ролі, MXL…)
```

## Встановлення

1. Встановити [Claude Code](https://claude.com/claude-code) і клонувати репозиторій.
2. Покласти вивантаження конфігурації в `configuration\` (через конфігуратор або `/1c-batch dump-config`).
   Для `/1c-batch` — скопіювати `.claude/skills/1c-batch/assets/.1c-devbase.ps1.example` у `.1c-devbase.ps1`
   і вказати параметри бази (файл не комітити).
3. Запустити Docker-контейнери `1c-rag` (проіндексувати цю ж конфігурацію) і `mssql-mcp`
4. Підключити MCP `atlassian` у `~/.claude.json` з особистим токеном.

**Одна конфігурація — одна копія проєкту:** 1c-rag індексує лише одну конфігурацію, тому для кожної конфігурації
потрібні свій контейнер 1c-rag і своя копія цього проєкту.

## Обмеження

- Індекс 1c-rag не містить підписок на події, регламентних завдань, модулів застосунку/сеансу,
  текстів запитів СКД і текстових макетів — їх агент читає з файлів вивантаження.
