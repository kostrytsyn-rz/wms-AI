# WMS-AI — рабочее место аналитика 1С

## О проекте

Проект для **аналитика**: разобраться, как задача реализована в конфигурации сейчас, найти похожие задачи в Jira
и подготовить разработчику понятный план реализации (задачу в Jira). Код конфигурации здесь **не пишется и не меняется**.

Конфигурация: **WMS**, платформа 8.3, режим совместимости 8.3.8, основной режим запуска — **обычное приложение**
(439 обычных форм `Form.bin` против 98 управляемых `Form.xml`).

Основной сценарий — `/analyze` (ошибка или доработка → анализ → причина / план, в чат).
Задача или комментарий в Jira — отдельно, `/jira-task`, **только по явной просьбе** пользователя.

**Одна конфигурация на проект.** 1c-rag индексирует только одну конфигурацию, поэтому на каждую конфигурацию —
свой Docker-контейнер 1c-rag и своя копия этого проекта. Выгрузка всегда лежит прямо в `configuration\`
(без вложенной папки с именем конфигурации); имя и версия — в `configuration\Configuration.xml`.
Если 1c-rag показывает объекты, которых нет в `configuration\` (или наоборот) — MCP подключён к контейнеру
другой конфигурации: скажи об этом пользователю и не продолжай анализ.

## Где искать конфигурацию и код

| Что | Где |
|---|---|
| Выгрузка конфигурации (XML + BSL) | `configuration\` (корень: `Configuration.xml`) |
| Модули обычных форм в виде `.bsl` (кеш) | `.formbin-cache\<тот же путь>\Forms\<Форма>\Ext\Form\Module.bsl` |
| Индекс кода и метаданных | MCP `1c-rag` |
| Данные (база с данними) | MCP `mssql-mcp` + скилл `/1c-sql-structure` |
| Постановки, история задач | MCP `atlassian` (Jira, Confluence) |

### Раскладка выгрузки

| Что ищем | Путь в `configuration\` | Чем читать |
|---|---|---|
| Модуль объекта / менеджера | `<Тип>\<Имя>\Ext\ObjectModule.bsl`, `ManagerModule.bsl` | 1c-rag; Read/Grep |
| Общий модуль | `CommonModules\<Имя>\Ext\Module.bsl` | 1c-rag; Read/Grep |
| Модули приложения и сеанса | `Ext\OrdinaryApplicationModule.bsl`, `Ext\SessionModule.bsl` | **только Read/Grep** (нет в 1c-rag) |
| Управляемая форма | `<Тип>\<Имя>\Forms\<Форма>\Ext\Form.xml` + `Ext\Form\Module.bsl` | `/inspect` (form-info); модуль — 1c-rag |
| **Обычная форма** | `<Тип>\<Имя>\Forms\<Форма>\Ext\Form.bin` | модуль — 1c-rag (`МодульФормы_<Форма>`) или кеш; элементы/обработчики — `/form-bin` |
| Общие формы (21 обычная) | `CommonForms\<Имя>\Ext\Form.bin` | **нет в 1c-rag** → кеш / `/form-bin` |
| Отчёт на СКД (65 из 82) | `Reports\<Имя>\Templates\<Макет>\Ext\Template.xml` (TemplateType = DataCompositionSchema) + `ObjectModule.bsl` | `/inspect` (skd-info) |
| Отчёт без СКД (17) | `ObjectModule.bsl` + модуль формы + MXL-макет | 1c-rag + `/inspect` (mxl-info) |
| Печатный макет MXL | `...\Templates\<Макет>\Ext\Template.xml` (TemplateType = SpreadsheetDocument) | `/inspect` (mxl-info) |
| Текстовые макеты с кодом | `...\Templates\<Макет>\Ext\Template.txt` (напр. `Catalogs\ЭлементыПравилРазмещения\Templates\*_ПредОбработка`) — код выполняется через `Выполнить()` | **только Read/Grep** |
| Подписки на события, регл. задания | `EventSubscriptions\*.xml`, `ScheduledJobs\*.xml` (обработчик — процедура общего модуля) | `/inspect` (meta-info); **нет в 1c-rag** |
| Роли и права | `Roles\<Имя>\Ext\Rights.xml` | `/inspect` (role-info) |
| Меню обычного приложения (153 интерфейса) | `Interfaces\<Имя>\Ext\Interface.bin` — текст в скобочном формате | Grep по имени объекта (`grep -l -a "АРМУпаковки" Interfaces/*/Ext/Interface.bin`) → в каких интерфейсах (меню ролей) есть объект |
| Тип макета (СКД / MXL / текст) | `...\Templates\<Макет>.xml` → `<TemplateType>` | Grep |
| **Хранимые процедуры / функции SQL** (~296 + ~44) | **не в выгрузке** — в базе; вызываются из 1С строкой `exec [dbo].[Имя]` через `МодульSQL.ВыполнитьЗапрос` (ADODB) | `mssql-mcp` (`OBJECT_DEFINITION`) по `/1c-sql-structure`; места вызова — Grep `exec\s+\[?dbo` |

### Порядок поиска кода

1. **1c-rag** — первым (`search_procedures_direct`, `search_1c_code`, `find_procedure_code`, `get_module_full_code`).
   Имена модулей в индексе: `МодульОбъекта`, `МодульМенеджера`, `Модуль` (общий модуль), `МодульФормы_<ИмяФормы>` (и обычные, и управляемые формы).
2. **Не нашлось в 1c-rag** или объект вне индекса (см. ниже) → Grep по `configuration\` **и** `.formbin-cache\`
   (`glob: "*.bsl"`). Без кеша код 439 обычных форм Grep не видит.
3. Кеш устарел или отсутствует → обнови: `powershell.exe -NoProfile -File .claude/skills/form-bin/scripts/form-bin-export.ps1 -ConfigPath configuration` (~2 с).
4. Результат 1c-rag расходится с файлами → верь файлам и скажи пользователю, что индекс устарел.
5. В коде `exec [dbo].[...]` / `МодульSQL.ВыполнитьЗапрос` → логика в **хранимой процедуре SQL**: прочитай её текст через
   `mssql-mcp` (раздел «Збережені процедури» в `/1c-sql-structure`). Не делай вывод «логики нет», не проверив SQL.
   Текст — из **preprod**, на продуктиве может отличаться; изменение процедуры — отдельный пункт плана (не входит в `.cf`).

### Покрытие индекса 1c-rag (проверено 2026-11-09)

- **Есть:** Обработки (92), Регистры сведений (90), Отчёты (82), Справочники (32), Общие модули (31), Перечисления (18), Документы (13), ПВХ (1) — с модулями объектов, менеджеров и форм (включая обычные формы).
- **Нет:** общие формы, подписки на события, регламентные задания, модули приложения/сеанса, тексты запросов СКД, текстовые макеты `Template.txt`.
- **Справка по синтаксису (`bslsyntax_*`) работает** (проверено 2026-11-09): глобальные функции, методы и свойства объектов, включая объекты обычного приложения (`ТабличноеПоле`). Поведение методов платформы — проверять по ней.
- В начале работы — `mcp__1c-rag__diagnose_database`. Если состав изменился — обнови этот раздел.

## MCP: правила

Все инструменты вызываются с полным именем `mcp__<сервер>__<инструмент>`.

**Подключение.** `1c-rag` и `mssql-mcp` — в `.mcp.json` проекта (включены в `.claude/settings.json` → `enabledMcpjsonServers`),
по умолчанию `http://localhost:9000/mcp` и `http://localhost:9001/mcp`. Другой Docker-контейнер (другая конфигурация) —
переменные окружения `RAG_MCP_URL` / `MSSQL_MCP_URL` или свои порты в `.mcp.json` копии проекта.
`atlassian` — на уровне пользователя (`~/.claude.json`): Jira одна для всех конфигураций, а токен личный и в проект не кладётся.

| Ситуация | Инструмент |
|---|---|
| Найти объект / его структуру | `search_1c_objects`, `list_metadata_objects`, `get_object_metadata`, `list_object_modules` |
| Найти код / процедуру | `search_procedures_direct`, `search_1c_code`, `search_1c_procedures` → `find_procedure_code`, `get_module_full_code` |
| Где используется, кто вызывает | `find_object_references`, `search_by_relationship`, `analyze_procedure_calls` |
| Похожая реализация (образец для разработчика) | `find_similar_procedures` |
| Индексы таблиц для запроса | `search_by_structure(indexed=True)` |
| Проверить гипотезу на данных | `mssql-mcp` `query_sql` (только SELECT, `TOP`) + `/1c-sql-structure` |
| Текст хранимой процедуры / функции, что она читает и пишет | `mssql-mcp` `query_sql`: `OBJECT_DEFINITION`, `sys.parameters`, `sys.sql_expression_dependencies` |
| Постановка, похожие задачи, как их сделали | `jira_get_issue`, `jira_search`, `jira_get_issue_development_info`, `confluence_search` |

- SQL — только SELECT, на регистрах и движениях — всегда `TOP N` и фильтр. Хранимые процедуры только читать, **никогда не `EXEC`**.
- Jira/Confluence: создание задач, комментариев, страниц — **только после согласования текста** с пользователем.
- MCP-сервер недоступен — скажи явно и работай с выгрузкой, не подменяй источник молча.
- `bslcheck_code` — только для диагностики найденного кода (явные дефекты); код в этом проекте не пишется.

## Скиллы

**Перед своими скриптами — проверь, нет ли скилла.** Не генерируй PowerShell/BAT для операций, которые покрывают скиллы.

Скрипты скиллов (`powershell.exe -File .claude/skills/...ps1`) запускай **через инструмент PowerShell**, а не Bash:
из Bash на этой машине они падают с «running scripts is disabled» (политика выполнения LocalMachine не задана).

| Скилл | Когда |
|---|---|
| `/analyze` | **Основной.** «Проанализируй / посмотри / проверь / почему так», ошибка, доработка, ключ Jira «разбери» → анализ текущей реализации → причина / план в чат. В Jira ничего не пишет |
| `/jira-task` | **Только по явной просьбе**: «поставь задачу», «добавь комментарий в KEY», «обнови / измени задачу» → черновик из анализа → «ок» → создание / комментарий / обновление |
| `/inspect` | Структура из XML: конфигурация, объект, управляемая форма, СКД, MXL, подсистема, роль |
| `/form-bin` | Обычные формы `Form.bin`: элементы, страницы, кнопки → обработчики, модуль; пакетная выгрузка модулей в кеш |
| `/1c-sql-structure` | SQL к базе 1С: объект ↔ view, расшифровка `_InfoRg326`, даты +2000, хранимые процедуры/функции (текст, параметры, зависимости) |
| `/1c-query-opt` | Задача про медленный запрос/отчёт: что именно предложить оптимизировать |
| `/1c-batch` | **Только выгрузка** свежей конфигурации: `dump-config` в `configuration` (спросить: полная или `update`), после — обновить кеш форм. `load-*`, `build-*`, `run-*` в этом проекте не используются |
| `/session-retro` | Ретроспектива сессии: что сработало, что нет, выводы |

## Режим работы

| Запрос | Что делать |
|---|---|
| Вопрос «где/как это сделано» | Ответить напрямую по 1c-rag/выгрузке, со ссылками `Объект → Модуль → Процедура` |
| Проанализировать, посмотреть, проверить: проблема, доработка, ключ Jira | `/analyze` — результат в чат, Jira не трогать |
| Создать задачу, добавить комментарий, обновить / изменить задачу | `/jira-task` |

- По умолчанию — анализ. Не предлагать создать задачу или комментарий, если пользователь об этом не просил.
- Уточняющие вопросы — до исследования; не спрашивать то, что можно найти самому.
- `/jira-task`: одна точка согласования — полный текст изменения. После «ок» — выполнить без дополнительных вопросов.
- Выводы — с доказательствами (код, метаданные, результат запроса); гипотезу помечать гипотезой.
- Обычные формы меняются только в конфигураторе — в задаче так и указывать.

## Правила

- Язык ответов — язык пользователя; имена объектов 1С — как в конфигурации (кириллица).
- Не изменять `configuration\` (кроме обновления выгрузки через `/1c-batch dump-config` по просьбе пользователя).
- Git: не коммитить `.1c-devbase.ps1`, учётные данные, ключи; не force push.
- Широкий поиск — через субагентов.
